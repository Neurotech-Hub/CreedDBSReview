# Manuscript

LaTeX source for the FLEX-DBS paper. One source builds both a PDF and a Word document.

## Building

### One-time setup (macOS)

```sh
brew install tectonic pandoc      # required for every build
brew install python               # only for regenerating Figures 4 and 5
brew install fswatch              # only for `make watch`
```

Tectonic downloads the LaTeX packages it needs on the first build, so the first run needs an
internet connection and takes longer. Tested with Tectonic 0.17 and pandoc 3.10.

### Build

From the repository root:

```sh
cd manuscript
make
```

This writes four files to `build/`:

| File | Contents |
|---|---|
| `flex_dbs.pdf` | Manuscript (Tectonic + BibTeX) |
| `flex_dbs.docx` | Manuscript for Word (pandoc + citeproc, styled by `templates/reference.docx`) |
| `flex_dbs_notes.pdf` | Working notes (`notes.tex`) |
| `flex_dbs_notes.docx` | Working notes for Word |

Other targets:

```sh
make pdf      # manuscript PDF only
make docx     # manuscript DOCX only
make notes    # working notes PDF and DOCX only
make figures  # regenerate figures/fig4_impedance.png and figures/fig5_bench.png
make watch    # rebuild the PDF on every save
make clean    # delete build/
```

`make` rebuilds only what changed. If you edit nothing and still want a fresh build, run
`make clean && make`.

### Figures

Figures 1–3 are static images in `figures/`; replace the file to update them. Figures 4 and 5
are generated by scripts from data elsewhere in the repository:

| Figure | Script | Input data |
|---|---|---|
| 4 | `figures/scripts/fig_impedance.py` | `../data/impedance/mousehatImpedance.xlsx` |
| 5 | `figures/scripts/fig_bench.py` | `../data/bench/*.jls` |

The first `make figures` creates a Python environment in `.venv/` (gitignored) with matplotlib,
numpy, scipy and pyjls. Because the generated PNGs are build inputs, `make` also regenerates a
figure automatically when its script or data is newer than the PNG.

### Before committing

The built PDF and DOCX in `build/` are tracked in git so collaborators can read them without
building. Run `make` before committing source changes so the committed outputs match the
source.

## Layout

| Path | Contents |
|---|---|
| `main.tex` | Title block and the order of sections |
| `sections/*.tex` | One file per section; edit these |
| `notes.tex` | Standalone document for the working notes |
| `sections/working_notes.tex` | Open items and pending data for the preprint; built only into the notes PDF, not the manuscript |
| `future_revisions.md` | Items deferred beyond the preprint; not built |
| `refs.bib` | Bibliography |
| `creed.sty` | PDF-only styling (fonts, margins, title format, natbib) |
| `figures/` | Images referenced by `sections/figures.tex` |
| `figures/fig1_architecture.png` | Figure 1, edited directly (not generated) |
| `figures/fig1_architecture.mmd` | Earlier Mermaid draft of Figure 1, kept for reference; not built |
| `figures/scripts/fig_impedance.py` | Builds Figure 4 from `../data/impedance/mousehatImpedance.xlsx` |
| `figures/scripts/fig_bench.py` | Builds Figure 5 from `../data/bench/*.jls` |
| `supplements/` | Supplementary files (schematic) |
| `literature/` | PDFs of cited papers, for checking citations; not built |
| `templates/reference.docx` | Word styles applied to the DOCX (copied from `creed_v81_draft.docx`) |
| `templates/elsevier-harvard.csl` | Citation style for the DOCX |

To restyle the DOCX, open `templates/reference.docx` in Word, change the styles (Normal, Heading 1–3,
Title, Subtitle, and so on), and save. pandoc uses only the styles, not the text.

## Citations

Cite with natbib: `\citep{key}` gives "(Author, 2020)" and `\citet{key}` gives "Author (2020)".
Keys live in `refs.bib`. The PDF uses BibTeX with `elsarticle-harv`; the DOCX uses pandoc's
citeproc with the Elsevier Harvard CSL, so both come out in the same author-year style. In the
DOCX the reference list is always placed at the end of the document.

## Keeping the DOCX faithful

pandoc reads the same `.tex` files, so write the body in plain LaTeX: `\section`, lists,
`longtable`, `\includegraphics`, `\emph`/`\textbf`, inline math. In particular:

- Don't define macros for manuscript text. The DOCX build turns macro expansion off, so they
  would not appear in Word.
- Write table column types in full with a trailing `{}`, as in
  `>{\raggedright\arraybackslash{}}p{0.3\linewidth}`. Without the `{}`, pandoc drops the first
  word of each cell.
- A list item that starts with `[` needs braces, `\item {[Pending]}`; otherwise LaTeX
  treats the bracket as the item label.

Section, table and figure numbers are typed by hand in headings and legends. Reviewer comments
from Word are kept as `% COMMENT` lines in the source.
